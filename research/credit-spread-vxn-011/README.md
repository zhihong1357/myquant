# Credit-spread changes lead Nasdaq-100 volatility (study 011)

Eleventh empirical study in myquant Stage 3, and the fourth real use
of the Stage 6c scaffold. Research question: does the latest available
BAA10Y credit-spread change predict the next-day VXN log change,
beyond VXN's own history and the SPX common-factor control?
This is the planner's rank-1 candidate pair after study 010 consumed
BAA10Y→VIX (6a, total score 1.00, adjacent supported edge E0026).
It is the first study to use the refreshed VXN panel (PR #25).

## Design

The predictor is the daily BAA10Y level change in basis points (not
the log return the planner draft names — a spread quoted in
percentage points has no meaningful log return). The target is the
VXN daily log change (VXN is an index level). The expected sign is
positive: credit-spread widening reflects credit stress, which
usually accompanies rising equity volatility. The draft's "positive,
out-of-sample component" refers to positive incremental explanatory
power (incremental R-squared above zero), not to a positive
coefficient.

The base model predicts the next-day VXN log change from VXN's own
lagged log change and the SPX log return; the augmented model adds
the lagged BAA10Y change. The test family has one test (the
primary), Holm-adjusted. Verdict criteria (study 003's three, no
cost gate — VXN is not tradable): Holm-adjusted primary p below
0.05, primary partial R-squared at least 0.005, holdout out-of-sample
incremental R-squared above 0. The cost gate is informational only
(gross sign-rule edge, no costs applied, study 003's precedent) and
carries no verdict weight.

The full design lives in `design.json`; the registered spec is in
`hypotheses/registrations/H0016/v1.json`.

Sample windows (21:00 UTC daily closes): train [2003-01-02,
2020-01-01), validation [2020-01-02, 2024-01-01), holdout
[2024-01-02, 2026-11-19), each separated by a one-day purge gap.
Minimum observations: 1000 / 500 / 300. Unlike study 009, the sample
is not truncated: VXN is still published, so the window runs to the
fetch date.

### Publication lag (the core PIT issue)

BAA10Y posts about a day later than other FRED series (6b evidence
probe 2026-11-18T21:45Z: BAA10Y latest 2026-11-16, VXNCLS already
2026-11-17). FRED daily values generally post on the next business day
(study 007, N=1), so BAA10Y's effective availability lag is
**2 trading days**: at the close of day t, the latest available
BAA10Y value is dated t-2, and the latest available change is the
change ending t-2. The predictor for the VXN log change over t+1
is therefore the BAA10Y change ending at t-2 — a lag-2 predictor by
value date, deliberately. The SPX control carries no lag: Yahoo posts
the close the same evening, so the SPX log change over day t is
knowable at the decision close (study 003's factor-alignment
precedent, SPX[t]). Both lags are applied in the trial's panel
construction via the study-007 lagged-changes module
(`myquant.studies.publication_lag.lagged_changes_on_index`); the PIT
store itself records `available_at` equal to the event time (adapter
limitation — see the design's known confounders). The fetch script
re-verifies the posting pattern behaviorally and records the observed
last dates in the manifest.

### Researcher decisions beyond the planner draft

1. Predictor is the level change in basis points, not the log
   return (see above).
2. The universe adds `index:sp500` as the common-factor control leg.
   The draft's research question assumes a common-factor control but
   names none; the lab convention (studies 001/003/008/010) is a
   third-asset control in the primary test. Lagged VIX is deliberately
   not the control: VIX and VXN are highly correlated
   equity-volatility indices, so a VIX control would absorb the common
   volatility factor and make the test overly conservative. TYVIX
   would truncate the sample at 2020; SPX returns are the natural
   equity common factor, and study 003 used SPX with predictor-day
   alignment. It enters unlagged (control_lag_steps=0) because Yahoo
   posts the close the same evening.
3. The BAA10Y predictor is lagged 2 trading days by availability
   (see above).
4. The cost gate is informational only (VXN is not tradable; VXN
   futures (VN) existed historically on CFE but are not in its
   current product list, and no free VXN futures price series exists
   to measure roll costs — Yahoo VN=F returns no data, verified
   2026-11-19), so the verdict takes three criteria instead of the
   draft's four. Study 003's precedent.

## Results

**Verdict: H0016 v1 REJECTED** (trial T0019, ledger record
`44686089ef56366aed448d23b43672a4dd868504511cd10be788a5f5b8228be4`).
Primary (n = 5,955, HAC max lag 5): coefficient −0.000097 per bp
(wrong sign vs the preregistered positive expectation), SE 0.000384,
p = 0.8001, Holm-adjusted p = 0.8001, partial R² = 2.29e-05 — 219x
below the preregistered minimum effect size of 0.005. The no-factor
upper bound is the same null (p = 0.6110), and the naive lookahead
alignment is also null (p = 0.8177), so the publication lag is not
what killed the effect. Reverse placebo (VXN → BAA10Y) is not
significant either (p = 0.2334). Walk-forward: all-OOS incremental R²
−0.000985; holdout (716 rows) +0.000024 — the holdout criterion
passes, but by an MSE difference of 9.7e-08, pure noise. The
informational cost assessment reports a gross sign-rule edge of
+0.306% per day with a 95% CI that includes zero (bootstrap p =
0.1714, sign accuracy 51.1%) — not a verdict criterion. One of three
verdict criteria passes; the two decisive ones fail by orders of
magnitude. MDE (partial R², 80% power) is 0.001316, so the study
rules out any effect at or above ~0.0013. Full results, robustness
and limitations: the study report
(`docs/studies/credit-spread-vxn-011.md`).

## Running

From the repo root, with the dev environment installed:

```bash
.venv/bin/python research/credit-spread-vxn-011/preregister.py
.venv/bin/python research/credit-spread-vxn-011/fetch_data.py
.venv/bin/python research/credit-spread-vxn-011/run_trial.py
```

Preregistration must precede any result-level analysis. Coverage
checks (date ranges, bar counts, missing bars) and the publication-lag
verification are the only pre-trial data contact allowed.
