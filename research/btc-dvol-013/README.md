# Lagged BTC returns lead BTC_DVOL changes (study 013)

Thirteenth empirical study in myquant Stage 3, and the sixth real
use of the Stage 6c scaffold. Research question: does the lagged
BTC daily log return predict the next-day BTC_DVOL log change,
beyond BTC_DVOL's own history and the ETH common-factor control?
This is the planner's rank-1 candidate pair after study 012
consumed BAA10Y→DGS10 (6a, total score 1.00, adjacent supported
edge E0030). It is the lab's first DVOL study — a new data source
(Deribit's BTC implied-volatility index) and the first study whose
panel is entirely crypto-native (24/7 calendar, no US trading days).

## Design

The predictor is the BTC daily log return (OKX BTC-USDT-SWAP 1D
candles, bars open 16:00 UTC), lag-1. The target is the BTC_DVOL
daily **log change** (DVOL is an index level like VIX, so the log
change is the target — unlike study 012's DGS10 yield target,
which took the level change in basis points). The expected sign is
**negative**: the classical leverage effect — negative returns
accompany rising volatility, so a lagged BTC fall should accompany
a next-day DVOL rise. The draft's "positive, out-of-sample
component" refers to positive incremental explanatory power
(incremental R-squared above zero), not to a positive coefficient.

The daily DVOL value is the **16:00 UTC snapshot** (the close of
the Deribit hourly DVOL row timestamped 15:00 UTC), aligned to the
OKX 1D bar grid — the daily DVOL endpoint timestamps points at
00:00 UTC, which would leave an 8-hour overlap between the
predictor and target windows. There is no FRED-style publication
lag: BTC prices and the DVOL index are both real-time.

The base model predicts the next-day DVOL change from DVOL's own
lag-1 change and the ETH log return; the augmented model adds the
lagged BTC return. The ETH control (not SPX) is a researcher
addition: the panel is a 24/7 crypto calendar and SPX has no
weekend values, so an SPX control would force dropping ~28% of
rows or violating the no-forward-fill rule. The test family has
one test (the primary), Holm-adjusted. Verdict criteria (study
003's three, no cost gate — BTC_DVOL is an index and no clean
straddle cost series exists): Holm-adjusted primary p below 0.05,
primary partial R-squared at least 0.005, holdout out-of-sample
incremental R-squared above 0. The cost gate is informational only
(gross sign-rule edge in log-change units per day, no costs
applied, study 003's precedent) and carries no verdict weight.

The full design lives in `design.json`; the registered spec is in
`hypotheses/registrations/H0018/v1.json`.

Sample windows (16:00 UTC daily closes): train [2021-03-24,
2024-01-01), validation [2024-01-02, 2025-01-01), holdout
[2025-01-02, 2026-11-20), each separated by a one-day purge gap.
Minimum observations: 500 / 300 / 300. The sample is the full
DVOL window (2021-03-24 to the fetch date): n = 2,065, far smaller
than the BAA10Y studies' 5,957, so the MDE is 0.003787 rather than
0.001316.

## Results

**H0018 REJECTED** (trial T0021, ledger record `302631f4…`,
recorded 2026-11-19T17:20:11Z). Primary: coefficient +0.100154
(wrong sign vs the preregistered negative expectation), SE
0.0828821, t = +1.208, p = 0.2269, Holm p = 0.2269, partial R² =
0.001195 (MDE 0.003787, threshold 0.005), n = 2,065. Holdout OOS
incremental R² +0.002538 (6 folds, 685 rows) is the only passing
criterion. No-factor bound also null (p = 0.4464). Same-bar naive
alignment also null (p = 0.3987) — the lag is not what killed the
effect. Reverse placebo nominally significant (p = 0.0317,
partial R² = 0.00334, descriptive only, below threshold).
Amplitude check (|BTC| → DVOL) nominally significant (p = 6.6e-06,
partial R² = 0.00993) but with a NEGATIVE coefficient and
descriptive only — consistent with DVOL level mean-reversion, not
a leverage channel; not promoted. Scan: lag 0 −0.2691
(contemporaneous leverage effect), lag 1 +0.0270 (tradeable
alignment, null). Informational cost gate: gross edge +0.000968
log-change units/day, CI includes zero, p = 0.4443, sign accuracy
53.7%.
